# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Voice Notes**: a Windows Electron app. A global hotkey (default Alt+Win) shows a floating pill that records a voice note to a local `.webm` file indexed in SQLite. A dashboard organises notes into nested folders (Inbox = unfiled), and plays, renames, moves (drag & drop, multi-select), stars, searches and deletes them, alongside markdown text notes (pages). **Home** (the default view) shows widgets the user picks: quick-add boxes that append `- entry` under today's `## D Mon YYYY` heading of a chosen page, and pinned pages rendered read-only. **Film mode** (tray/Settings toggle, off at every launch) keeps the last 60 s of system audio in memory; Alt+Win+Shift saves the last N s as a `rewind` note. Mic notes pause playing media (play/pause key) and resume after. Every note stores the foreground window title and a cleaned `show` label. **Transcription** (on demand, per note or selection) sends a note to the user's own OpenAI-compatible Whisper server (e.g. vLLM), or to the **Built-in** provider: a pinned whisper.cpp CPU build plus a model the user picks, downloaded on demand from upstream (GitHub release, Hugging Face; SHA-256 checked) and run as `whisper-server.exe` on 127.0.0.1 behind the same client, unloaded after 5 min idle. Both are set up on the Transcription page; the transcript is stored on the note, editable and searchable. Cloud providers are listed as Coming soon. **Review later**: dragging a link or text from a browser onto the visible pill (idle or "Saved", never while recording) appends a `- [ ] …` line under today's heading of the built-in Review later page (can't be deleted; its Home card is `locked` and always first). **Dictation**: Ctrl+Win (hold, or double-tap for hands-free; its own `HotkeyGesture`) records the mic, sends the clip to the same Whisper server and pastes the text at the cursor of the focused app (clipboard + Ctrl+V once the modifiers are up, previous clipboard restored 500 ms later). Texts (never audio) are kept 24 h in the Dictation panel. Dictation and voice notes exclude each other. **Voice to calendar** (Connectors page switch `voiceToCalendar`, on by default, per PC; acts only while Google Calendar is connected or needs reconnect): a dictation whose first words are "calendar" (or "calender"), "add (an) event" or "add to (my) calendar" goes to Quick Add instead of being pasted (`src/shared/calendar-command.ts` `parseCalendarCommand` strips the trigger and lead-ins like "set up a", "remind me to"); the pill shows "Added · …" (`done` state), a failure shows why and pastes the text; the panel keeps it prefixed "📅". **Account (optional)**: Google sign-in through Supabase Auth (project `tpadlhyraittxehfvshc`, Mumbai); chip at the bottom of the sidebar, Account page with Sign out. **Sync**: signed in with sync turned on ("Sync this PC" on the Account page, asked once after sign-in), notes, pages, folders and the synced settings stay in step between PCs through the `sync` Edge Function (C1). Audio and page images follow (C2): uploaded after each sync through 2-minute signed Storage URLs the function hands out, downloaded on first play (a note from another PC is `remote`, with a cloud icon) or first view; the server removes files whose note or page is gone. Instant pings (C3): after a push with changes the function broadcasts on the private Realtime topic `sync:<user_id>` (only the account can listen, no one but the function can send) and the other running PCs sync at once; the 5 min timer still covers missed pings. **Connectors**: signed in, the Connectors page connects Google Calendar once per account (every PC sees it): a separate opt-in consent (`calendar.events`) through the `connectors` Edge Function, which keeps the refresh token (AES-GCM, `CONNECTORS_KEY`) and hands main short-lived access tokens; main calls the Calendar API itself. A **Today's calendar** Home card (`calendar` widget, no page, at most one) lists today's primary-calendar events; a click opens the event in Google Calendar, and its one-line box adds an event through Google's Quick Add ("Lunch tomorrow 1pm"). While connected, a **Calendar** tab (sidebar, under Home) shows the primary calendar as a month grid: event details read-only with Open in Google Calendar, + New event (title, date, start–end or all day). After consent the browser lands on a page the app serves on `127.0.0.1` (Edge Functions on `*.supabase.co` rewrite `text/html` to `text/plain`, so the function only redirects). Reminders on notes are a later round. Specs: `docs/superpowers/specs/`; plans: `docs/superpowers/plans/`.

## Commands

- `npm start`: run in dev (Electron Forge + Vite, HMR for renderers)
- `npm test`: Vitest unit tests. Runs **under Electron as Node** (`ELECTRON_RUN_AS_NODE=1`) because `better-sqlite3`/`uiohook-napi` are rebuilt for Electron's ABI by `postinstall`. Never run vitest with plain `node`/`npx vitest`. Filter: `npm test -- gesture`.
- `npm run typecheck`: `tsc --noEmit`
- `npm run package` / `npm run make`: packaged app / Squirrel installer in `out/`
- `npm run test:e2e`: runs `package` (emits the production Vite build to `.vite/`), then Playwright `_electron` tests in `tests/e2e/` (shared launcher `tests/e2e/launch.ts`; screenshots to `.superpowers/shots/`). Home is the default view, so specs click Inbox first (`getByRole('button', { name: /^Inbox/ })`). Stop any running `npm start` first: its watcher rewrites `.vite/` with dev-server URLs. Close the packaged app before packaging (it locks `out/`). The launcher sets `colorScheme: null` so Playwright doesn't force light mode. They launch `electron .` with the dev binary, not the packaged exe, because packaged fuses disable the Node inspector Playwright needs.
- Packaging: Vite bundles everything except `better-sqlite3`/`uiohook-napi`/`koffi`; `forge.config.mts` `packageAfterCopy` copies them (plus `node-gyp-build`, and `koffi` whole with its `@koromix/koffi-win32-x64` binary) into the package. Add any new native module there and to `vite.main.config.mts` externals. (`fflate` is pure JS and bundled.)

## Data

`%APPDATA%/Voice Notes/`: `recordings/<uuid>.webm`, `images/<uuid>.<ext>` (pasted/dropped page images), `voice-notes.sqlite`, `settings.json`, `logs/`. Folders are database rows only (migration #2); notes carry `source` mic/system/both (migration #3) and `kind` note/rewind, `window_title`, `show`, `starred` (migration #4); notes gain `transcript`, `transcript_lang`, `transcribed_at` (migration #6; `''` = no speech; setting it never bumps `updated_at`); text notes are the `pages` table (migration #5: title, markdown body stored exactly as typed, folder, starred); deleting pages removes images no other page references and prunes their Home widgets; audio files never move. `settings.json` `transcription` (`provider` server/local/null, normalised `baseUrl`, `model`, `localModel`; a `local` provider whose model file is gone falls back to null at boot) and `transcribeLanguage`; built-in files live in `whisper/` (`engine/<tag>/`, `models/`, `server.pid`); the sign-in session lives only in `session.json` (safeStorage-encrypted, main only); the API key lives only in `secrets.json` (`safeStorage`-encrypted, never sent to a renderer). `homeWidgets` lists the Home cards in order (`quick-add` with `label` + `pageId`, `page`, or `calendar` with no page (`keepExisting`/`pruneWidgets` keep it; an older build would drop it, so update every PC); optional `w`/`h` spans, `locked` for the Review later card, which `removeWidget`/`unpinPage` keep and main re-adds via `ensureLocked`); `laterPageId` names the built-in page; no migration. Migration #8 (sync prep): notes, pages and folders gain `deleted_at` (deletes are tombstones: hidden from every list/get, files removed at once, rows purged 30 days later at boot once no outbox entry needs them) and `version` (server version last synced; 0 = never); tables `outbox` and `sync_state`. Migration #9 (sync files): `notes.status` gains `remote` (audio in the account, not on this PC; `reconcile` keeps it) and table `file_outbox`. Synced settings are only `homeWidgets`, `transcribeLanguage` and `laterPageId` (`SYNCED_KEYS`); everything else in `settings.json` stays on the PC. `updateSettings(patch, { record: false })` applies settings pulled from the account. The server rules (applied once per mutation id, body conflicts → "(conflict, PC)" copy while appends and ticks are replayed, folder loops refused, name clashes numbered, deleted folders re-home their contents, delete wins, prefs last-write-wins) are pinned by `tests/unit/sync/reference-server.ts`: the contract the Supabase side must match; `tests/unit/sync/convergence.test.ts` runs two real stores against it. The same rules run in the Edge Function (`SyncCore`), and `tests/unit/sync/contract.ts` runs them against memory and Postgres (PGlite, dev only). Unit tests run with `maxWorkers: 6` (each worker is an Electron process). Dictations are the `dictations` table (migration #7: text, app label, created_at; pruned to 24 h at boot and hourly); settings `dictationHotkey`/`dictationHotkeyLabel` (default Ctrl+Win, must differ from the recording and rewind combos) and `dictationSound`. Override the data dir with env `VOICE_NOTES_USER_DATA` (used by e2e). `VOICE_NOTES_TEST=1` exposes `globalThis.__voiceNotes` in main for Playwright and skips the global keyboard hook (so a person typing during a test run can't interfere). `launch({ userData })` reuses a data dir (relaunch tests); `launch({ fakeAudioFile })` feeds a WAV to the fake mic, e.g. `tests/e2e/fixtures/silence.wav`. Under fake devices the **loopback stream is the fake input too** (`tone.wav` = "media is playing"). Test hooks also expose `rewind()`, `pagesChanged()` (after editing `store.pages` directly), `openedExternal` (URLs the dashboard asked to open in the browser), `transcription` (`idle()` waits for queued jobs; e2e points it at a fake OpenAI-compatible server), `setForeground(fn)` (no real foreground window in tests) and `mediaPresses()` (auto-pause only counts presses under `VOICE_NOTES_TEST=1`), `dictationGesture` (what Ctrl+Win does) and `pasted` (texts a dictation would have pasted; no real paste under test), `sync` (`useServer(url)`: a local test server, e.g. `tests/e2e/fixtures/sync-server.ts`, which also serves signed file URLs from its `bucket`; `useToken(fn)`; `now()`; `ping(from)`: a Realtime ping as if PC `from` pushed), `account` (`setTestSession(info)`: signed in/out without Google; under test the service never runs `init()` or opens a browser), `connectors` (`useServer(url)`: `tests/e2e/fixtures/connectors-server.ts`, the function's handler over memory with a fake Google, also serving `/calendar/v3`; `useToken(fn)`; `service`), `localWhisper` (`setTestOverrides({ catalog, spawn: { script } })`: serve fake downloads and run `tests/e2e/fixtures/fake-whisper-server.mjs` instead of the engine).
